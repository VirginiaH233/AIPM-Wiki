# 数据合规红线:用户数据能不能用来训练

> 本文不构成法律意见。数据合规政策与法规更新频繁,请以厂商官方最新政策与国家最新法规原文为准,重大项目务必咨询法务或合规专业人士。

## 为什么 PM 必须懂这件事

"能不能把用户对话数据拿去训练模型"这个问题,表面看是法务和数据安全团队的职责,但实际决策经常卡在产品设计环节:要不要在设置里加一个"数据用于改进"的开关?默认是开还是关?收集用户数据时的告知文案怎么写?这些都是 PM 要直接拍板或者主导设计的产品细节,懂政策边界,才能在设计阶段就把合规做进产品,而不是上线后被动整改。

## 三家大模型厂商的训练数据政策对比(2026年7月)

以下对比基于三家厂商官方隐私政策/帮助中心页面梳理,消费者产品和企业/API 产品的政策存在明显差异,不能混为一谈。

| 厂商 | 消费者产品默认策略 | 消费者产品是否可控 | 企业/API 产品默认策略 |
|------|-------------------|---------------------|------------------------|
| Anthropic(Claude) | Free/Pro/Max 自 2025 年 9 月起默认**会**用于训练(隐私设置中"Improve Claude for everyone"开关默认开启),开启状态下数据可去标识化保留至多 5 年 | 可主动关闭(opt-out),关闭后新对话不用于训练、保留期回到约 30 天;但被安全系统标记复核的对话,即使关闭训练,仍可能被用于安全类模型改进(2026 年 6 月更新的隐私政策明确了这一例外) | Claude for Work、Enterprise、API 数据默认**不**用于训练模型 |
| OpenAI(ChatGPT) | Free/Plus/Go/Pro 等消费者计划,默认**会**用于改进模型,可在数据控制中手动关闭("不在我的内容上训练") | 可关闭,关闭后新对话不再用于训练 | Business、Enterprise、Edu 及 API 平台数据默认**不**用于训练或改进模型,除非客户显式选择共享(如 Playground 反馈) |
| Google(Gemini) | 免费版 Gemini Apps 默认**会**用于训练与人工复核,可在"Gemini Apps Activity"中关闭,或使用"临时聊天"模式 | 可关闭;关闭后数据默认约 30 天内删除(未开启训练时) | Workspace 企业版与 Vertex AI/API 默认**不**用于训练公开模型,管理员可进一步缩短或禁用提示词留存 |

几个需要特别注意的细节,直接影响产品文案和设置项设计:

- **"关闭训练开关"≠"数据完全不被使用"**。三家厂商都存在安全审核类的例外:Anthropic 明确说明被标记为安全复核的对话,不受用户训练开关约束;Google 的人工复核样本即便关闭活动记录,已被复核的对话仍可能保留更长时间(最长可达三年)。这个"安全例外"是产品隐私文案里最容易被遗漏、也最容易引发用户不满的一点,应该在隐私说明里明确写出来,而不是等用户自己发现。
- **消费者产品 vs 企业/API 产品的界限,是三家厂商共同的分界线**。如果你的产品是调用某家厂商的 API 或使用其企业版服务来构建自己的 AI 功能,通常默认不会被该厂商用于训练其基础模型——但这不代表你自己采集的用户数据可以随意用于**你自己**的模型训练,那是另一层需要单独设计告知与授权机制的问题。
- **数据保留期限和"是否训练"是两件事**,不要在产品文案里混为一谈。即使关闭训练,数据出于安全/客服排查等目的仍可能保留一段时间(通常 30 天左右,具体以各厂商当期政策为准)。

## 中国监管要点:以《生成式人工智能服务管理暂行办法》为核心

对于面向中国用户提供生成式 AI 服务的产品,《生成式人工智能服务管理暂行办法》(国家互联网信息办公室等七部门联合发布,2023年8月15日起施行)是最基础的合规依据,与数据直接相关的核心条款包括:

| 条款方向 | 要点 |
|----------|------|
| 训练数据来源合法性 | 要求使用具有合法来源的数据和基础模型,采取有效措施提升训练数据的真实性、准确性、客观性、多样性,不得侵害他人知识产权 |
| 数据标注规范 | 开展数据标注的,应当制定清晰、具体、可操作的标注规则;开展标注质量评估,抽样核验标注内容准确性;对标注人员进行必要培训 |
| 个人信息保护 | 涉及个人信息的,依法承担个人信息处理者责任;不得非法留存能够识别使用者身份的输入信息和使用记录;需按用户请求及时处理个人信息的查阅、复制、更正、删除等请求 |
| 生成内容标识 | 对图片、视频等生成内容,按深度合成相关规定进行标识 |

除此之外,涉及用户个人信息的产品还必须同时遵守《网络安全法》《数据安全法》《个人信息保护法》(PIPL)这三部上位法——生成式 AI 专项办法不能替代这三部法律的一般性要求,尤其是 PIPL 中关于"最小必要原则""单独同意""数据主体权利(查阅/更正/删除/可携带)"的规定,依然是判断产品设计合规与否的基础标准。

**数据出境**是很多出海或使用海外大模型 API 的产品容易忽视的一块。根据国家网信办发布的政策问答及《促进和规范数据跨境流动规定》的最新执行情况(截至 2026年3月的两周年总结通报):

- 年度累计向境外提供 100 万人以下个人信息(不含敏感个人信息达 1 万人)的,可以豁免申报或采用**标准合同备案/个人信息保护认证**等相对轻量的合规路径;
- 达到年度累计 100 万人以上,或敏感个人信息 1 万人以上的,需要申报**数据出境安全评估**;
- 2025年10月发布的《个人信息出境认证办法》进一步明确了认证路径的适用情形与申请方式;
- 数据出境安全评估结果的有效期已从 2 年延长至 3 年,可申请再延长 3 年。

如果你的产品会把中国用户的对话数据传给部署在境外的大模型 API(比如直接调用海外厂商的 API),这本质上就是一次个人信息出境行为,需要评估是否落入上述申报或备案的门槛,而不能想当然认为"调用 API 不算数据出境"。

## PM 实操清单

把上述政策和法规转成产品设计和流程中可以落地检查的动作:

**收集与告知**
- [ ] 隐私政策/用户协议中,是否用用户能看懂的语言明确说明"你的对话是否会被用于训练模型"
- [ ] 是否在关键节点(首次使用、设置页)提示用户数据使用方式,而非只藏在冗长的隐私政策里
- [ ] 涉及敏感个人信息(如医疗、金融、生物识别)的场景,是否做到 PIPL 要求的"单独同意",而非和普通条款打包勾选

**退出机制**
- [ ] 是否提供关闭"数据用于模型改进/训练"的开关,且关闭操作足够显眼、易操作
- [ ] 是否明确告知用户:关闭开关后是否仍存在安全审核等例外情形
- [ ] 是否支持用户查询、导出、删除自己的历史数据(对应 PIPL 的数据主体权利)

**脱敏处理**
- [ ] 进入标注/训练流程前,是否对用户身份信息(姓名、手机号、账号等)做去标识化或匿名化处理
- [ ] 标注团队(尤其外包)能否接触到未脱敏的原始数据,若能接触,是否有额外的保密协议和权限管控(参见[标注规范怎么写](annotation-guideline.md)中的内部/外包协作章节)

**数据出境**
- [ ] 是否使用了境外部署的大模型 API 或云服务,是否评估过这构成个人信息出境
- [ ] 出境数据量是否触及数据出境安全评估、标准合同备案或认证的申报门槛
- [ ] 涉及出境的第三方(模型厂商、云服务商)是否有明确的数据处理协议,约定用途限制和留存期限

**内部流程**
- [ ] 是否有法务/合规角色在产品设计阶段(而非上线前审核阶段)参与评审
- [ ] 数据回流闭环(参见[冷启动与数据飞轮](cold-start-and-data-flywheel.md))中的每个环节,是否都明确了合规责任人

## 小结

用户数据能不能用于训练,答案永远是"看场景":消费者产品和企业/API 产品的默认规则不同,厂商政策和所在国监管要求还要叠加判断,任何一刀切的"能"或"不能"都是不负责任的简化。作为 PM,最稳妥的做法是把"数据从哪来、用到哪去、用户是否知情、能否退出"这四个问题在产品设计阶段就问清楚,并且建立机制持续跟踪政策变化——这类政策每年甚至每季度都在调整,今天写好的合规清单,半年后可能就需要更新。
