# AI 产品指标体系：从业务结果到成本与风险

AI 产品不能用一个“准确率”概括好坏。用户是否愿意使用、任务是否真的完成、模型是否遵守边界、系统是否足够快、每项任务是否负担得起，分别属于不同层级。AI PM 的工作是把这些指标组织成一棵能解释因果、发现问题、支持决策的指标树。

> **事实**：官方评测指南强调要围绕具体任务定义成功标准，并持续比较模型、提示和系统变更；业务结果、模型效果和系统运行指标不是同一个概念，不能互相替代。见文末资料。
>
> **建议**：指标树先写“用户价值和业务结果”，再向下拆 AI 效果、系统表现、成本与风险；上线后看分层趋势和分群差异，不要只盯一个总平均。

## 一、先画指标树：一个北极星，四个支柱

可以用“有效完成的用户任务”作为常见的价值主线，再根据产品类型调整：

```text
用户/业务价值：用户以可接受的成本完成了有价值的任务
├─ 业务指标：采用、任务完成、后续业务结果、留存/转化、人效
├─ AI 效果指标：正确性、相关性、引用/依据、工具成功、拒答质量、安全
├─ 系统指标：延迟、错误、可用性、吞吐、轨迹完整性、服务稳定性
└─ 成本指标：模型调用、工具/基础设施、存储、人工复核、单位任务成本
```

这棵树不是“必须使用某一个北极星指标”，而是要求每个产品都能回答：**业务结果由哪些 AI 体验推动，AI 体验又受哪些系统与成本约束？**

## 二、四层指标怎么定义

### 1. 业务指标：有没有创造结果

业务指标必须对应真实用户行为或业务结果，而不是把模型分数直接当成价值。常见方向包括：

| 方向 | 指标例子 | PM 要补充的定义 |
|------|----------|----------------|
| 采用 | 功能使用率、有效启动率、重复使用率 | 谁是有资格使用的用户，什么叫一次有效使用 |
| 任务 | 任务完成率、用户采纳率、人工接管率 | 完成由什么业务证据确认，部分完成如何计入 |
| 体验 | 满意度、点踩率、追问率、取消率 | 反馈是否按任务类型和用户分群拆开 |
| 效率 | 单任务处理时长、人工处理量、等待时间 | 节省的是用户时间还是把工作转移给了人工 |
| 经营 | 转化、留存、复购、收入或成本回收 | 需要实验或对照才能支持因果判断 |

不要把“用户使用了 AI”直接解释成“用户得到了价值”。例如用户频繁追问可能说明功能有吸引力，也可能说明第一次回答没有解决问题；需要结合任务成功、追问原因和人工结果判断。

### 2. AI 效果指标：模型和 Agent 做得对不对

按任务选择指标，不要为了统一而强行使用“准确率”：

| 任务类型 | 效果指标方向 |
|----------|--------------|
| 分类/抽取 | 正确率、召回率、F1、字段完整率、格式合规率 |
| 生成/总结 | 事实正确性、相关性、完整性、风格/rubric 得分、引用可验证性 |
| RAG | 检索覆盖、检索排序、依据一致性、答案正确性、无依据时的拒答质量 |
| Agent | 任务成功率、必要步骤完成率、工具业务成功率、有效重试率、人工接管率 |
| 安全 | 越权拦截率、敏感信息泄露率、风险动作确认率、误拒率 |

对主观任务，指标必须绑定 rubric 和抽检校准；对高风险任务，安全指标通常是上线闸门，而不是可以用业务转化抵消的普通分数。评测集、标注和 Badcase 处理方法见[模型与产品效果评估](../model-evaluation/README.md)。

### 3. 系统指标：能不能稳定提供服务

系统指标关注“AI 结果被用户看到和使用的条件”：

- **延迟**：请求排队、首 token、完整响应、工具往返、任务总时长；
- **稳定性**：可用性、超时率、错误率、限流率、重试率、任务中断率；
- **容量**：并发、吞吐、队列长度、上下文长度和资源利用率；
- **可观测性**：轨迹完整率、工具结果可关联率、日志脱敏成功率；
- **体验状态**：加载、流式、等待确认、转人工和恢复任务的成功率。

平均延迟很容易掩盖长尾，建议按业务场景看分位数，并把“用户等待确认”与“系统无响应”分开。对于 Agent，还要按任务步骤和工具拆解，否则无法判断慢在模型、网络、第三方服务还是人工环节。

### 4. 成本指标：每一项价值花多少钱

成本应从“每次调用”上升到“每个有效任务”：

```text
单次调用成本 = 输入 token 成本 + 输出 token 成本 + 相关工具/基础设施成本
单项任务成本 = 该任务全部调用与工具成本 + 人工确认/接管成本
单位价值成本 = 总成本 ÷ 有效完成任务数
```

还应监控：成本/活跃用户、成本/租户、不同模型层级成本、重试带来的额外成本、缓存命中率、长任务成本分布和预算消耗速度。单价、调用量和 Token 估算方法见[AI 产品成本测算入门](../cost-and-tech/llm-cost-101.md)；缓存、批处理和模型路由见[降本手段盘点](../cost-and-tech/cost-optimization.md)。

## 三、从指标树到诊断链路

上线评审时，可以把指标写成一条假设链：

```text
功能触达
  → 用户愿意启动
  → Agent 正确完成任务
  → 用户采纳或减少人工接管
  → 业务结果改善

其中每一步都受到：效果、延迟、稳定性、安全和单位成本约束
```

每个节点要配一个**主指标**和一组**诊断指标**：

| 节点 | 主指标 | 诊断问题 |
|------|--------|----------|
| 启动 | 有效启动率 | 用户是否理解能力边界？入口是否打扰？ |
| 完成 | 任务成功率 | 哪个步骤、工具或数据源最常失败？ |
| 采纳 | 用户采纳率/人工接管率 | 结果不可信、不可编辑，还是业务流程不允许直接使用？ |
| 业务结果 | 场景对应的业务指标 | 是否有对照组？结果变化是否来自其他活动？ |
| 可持续 | 单项任务成本、长尾延迟 | 规模扩大后是否仍能承受？ |

这样可以避免“转化没涨，所以模型要继续调”的单一路径。问题可能出在入口、结果展示、权限、流程、价格、等待时间或评测集与线上分布不一致。

## 四、指标冲突：先定硬约束，再做优化

AI 产品的指标经常互相拉扯：

| 冲突 | 常见现象 | 建议的决策顺序 |
|------|----------|----------------|
| 效果 vs 延迟 | 更强模型更慢，长回答更完整 | 先确定任务最低质量，再按场景分层模型/输出和异步化 |
| 效果 vs 成本 | 增加上下文、重试或大模型提升分数 | 看单位有效任务成本，评估提升是否转化为真实结果 |
| 自动化 vs 安全 | 放宽权限和自动执行能提高完成率 | 安全、合规和不可逆风险是硬闸门，不能用转化抵消 |
| 拒答 vs 采用 | 更保守的策略减少风险，也可能降低覆盖 | 区分合理拒答和误拒，设计转人工/补充信息路径 |
| 平均值 vs 长尾 | 平均效果好，少数高风险失败 | 分层看高风险、长尾和关键租户，设置一票否决项 |
| 使用量 vs 效率 | 追问更多，活跃和调用量上升 | 结合一次解决率、完成时长和成本，避免奖励无效对话 |

**建议的指标优先级**：安全与合规硬约束 → 任务成功和用户价值 → 体验/系统底线 → 单位成本和规模效率 → 长期增长。具体顺序应由业务风险决定，医疗、金融、权限和外发场景不能套用低风险内容产品的优先级。

## 五、上线前后怎么监控

### 上线前：为每个指标写“基线—上线线—目标线”

| 项目 | 要写清的内容 |
|------|--------------|
| 基线 | 现有规则、人工流程或旧版本的结果和观测周期 |
| 上线线 | 不达标不能上线的质量、安全、稳定性、成本和延迟条件 |
| 目标线 | 上线后持续优化的方向，不把长期目标伪装成上线必达 |
| 分群 | 用户、租户、任务类型、模型层级、工具和数据新鲜度 |
| 责任人 | 每个指标谁看、谁解释、谁有权降级或回滚 |
| 行动 | 触发告警后是限流、关闭工具、切模型、转人工还是暂停发布 |

阈值不应凭空复制别的产品。可以先用历史基线和风险等级确定，再通过灰度验证；高风险安全事件、权限越界和敏感数据泄露通常直接作为阻断条件。

### 上线后：看趋势、分布和组合指标

上线监控至少分三层：

1. **实时层**：错误、超时、队列、工具失败、越权拦截、费用异常和高风险告警；
2. **日/周运营层**：任务成功、转人工、用户反馈、Badcase 类型、成本/任务和延迟分布；
3. **版本复盘层**：模型/Prompt/工具变更前后，离线评测、灰度分群和业务结果的对照。

监控要支持从指标跳到样本和轨迹：先发现“某任务成功率下降”，再定位“哪个用户分群、哪个工具、哪个模型版本、哪类 Badcase”造成变化。Agent 轨迹追踪方法见[Agent 评测与可观测性](agent-evaluation-and-observability.md)。

## 六、AI PM 指标评审清单

- [ ] 指标树从业务结果出发，且每层指标有明确公式、分母和数据来源。
- [ ] 业务、AI 效果、系统、成本和安全指标没有混为一个总分。
- [ ] 任务成功有可验证证据，主观任务有 rubric，安全指标有独立闸门。
- [ ] 指标能按用户、任务、模型、工具、版本和数据新鲜度分层。
- [ ] 已区分基线、上线线和长期目标线，避免用空泛的“效果好”验收。
- [ ] 成本按有效完成任务计算，并监控重试、长任务和人工接管的额外成本。
- [ ] 指标冲突有预先约定的决策顺序，出现风险时知道谁能降级或回滚。
- [ ] 上线后看板可以从趋势跳到样本、轨迹和 Badcase，形成闭环。
