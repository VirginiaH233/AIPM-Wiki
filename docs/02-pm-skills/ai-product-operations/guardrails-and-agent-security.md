# AI 安全与 Agent 权限：把“能做什么”变成可治理的边界

Agent 安全不是在回答末尾加一个内容过滤器，而是要保护一条完整链路：用户输入、模型上下文、检索内容、网页/文件、工具权限和外部副作用。只要 Agent 能读取或改变真实世界，就必须把**提示词安全、数据安全、身份权限、动作确认、审计和人工兜底**一起设计。

> **事实**：OWASP 的 LLM 应用安全风险中包含 Prompt Injection、敏感信息泄露和过度代理权限等问题；NIST AI RMF 将风险管理分成 Govern、Map、Measure、Manage 等持续活动。安全边界不能只依赖模型是否“听话”。
>
> **建议**：把外部内容默认视为不可信数据，把模型视为提出计划的组件，把真正的授权和执行放在可验证的服务端策略上。

## 一、先画威胁模型：哪些内容可以影响 Agent

```text
用户输入 ───────┐
系统指令/策略 ───┼→ 模型上下文 → 计划/工具调用 → 工具服务 → 外部系统/副作用
检索文档/网页 ──┤                         ↑
上传文件 ───────┘                  权限、策略、人工确认
```

产品评审时至少区分四类信任边界：

| 来源 | 默认信任级别 | 处理原则 |
|------|--------------|----------|
| 系统策略、服务端权限 | 受控 | 版本管理、代码评审、变更可追踪 |
| 用户指令 | 需要理解但不等于授权 | 仍受账号、租户和动作权限约束 |
| 检索文档、网页、邮件、附件 | 不可信数据 | 可以引用和分析，不能直接改写系统策略 |
| 工具返回与外部系统 | 需验证 | 校验来源、范围、格式和业务状态 |

### 事实、建议与推测要分开

- **事实**：某个模型或协议文档明确规定的行为，附官方链接；
- **建议**：为了降低产品风险而采取的设计选择，写清适用条件；
- **推测**：无法从公开信息确认的系统实现，只能写成“可能”“需要验证”，不能当成产品事实。

这一划分尤其适用于案例拆解：看到 Agent 能搜索网页，并不能推断它一定使用了某个协议、某个模型或某种权限架构。

## 二、Prompt Injection：指令与数据不能混为一谈

Prompt Injection 可以是用户直接要求模型忽略原有规则，也可以藏在网页、邮件、代码、PDF 或知识库文档中，诱导 Agent 泄露信息或调用工具。间接注入更容易被忽略，因为用户不一定看到了那段内容。

### 产品层缓解方法

1. **标记数据边界**：把用户指令、系统策略、检索材料和工具结果分成清晰的上下文区域，并明确“文档内容是待分析数据，不是新指令”。
2. **最小化上下文**：不把与当前任务无关的密钥、完整用户资料、内部策略和历史对话塞给模型。
3. **工具白名单**：模型只看到当前场景必需的工具；高风险工具默认不可用，而不是挂上后靠模型自觉不调用。
4. **服务端授权**：工具执行前重新检查用户身份、租户、资源和参数范围；Prompt 里说“我已获授权”不能代替真实授权。
5. **高风险动作确认**：涉及外发、删除、付款、权限变更等动作时，将计划和影响展示给用户或人工审核者。
6. **输入与输出检测**：对网页、附件和工具返回做格式、来源、敏感信息和异常指令检测，但把检测当作一层防线，而不是唯一防线。

**建议**：不要承诺“用一条更强的系统 Prompt 就能彻底防住 Prompt Injection”。在产品上应假设模型可能被误导，并通过权限隔离、动作确认和可回滚执行降低后果。

## 三、越权工具调用：避免“过度代理权限”

Agent 的工具地图最好先按“读什么”和“改什么”画出来：

| 工具类型 | 示例 | 默认策略 |
|----------|------|----------|
| 只读 | 搜索、查订单、读知识库 | 按用户和租户过滤；记录数据来源 |
| 可逆写入 | 创建草稿、添加标签、生成待办 | 限定资源范围，提供撤销或预览 |
| 不可逆/外部副作用 | 删除、付款、发邮件、公开发布 | 默认阻断或待确认；执行后保留证据 |
| 权限/身份类 | 邀请成员、改角色、生成令牌 | 高风险；需要更强身份校验和人工兜底 |

### 最小权限的落地清单

- 为每个 Agent 场景创建明确的工具 allowlist，而不是复用管理员工具包；
- 令牌只授予当前用户、租户、资源和动作所需的最小范围，并设置过期时间；
- 对参数做服务端类型、范围、目标地址、数量和敏感字段校验；
- 对重复请求使用幂等键或先查执行状态，避免重试造成重复副作用；
- 对批量动作设置数量、金额、时间和调用频率上限；
- 支持 dry-run/预览模式，让用户先看到计划和变更差异；
- 关键工具独立记录授权决策，不把“模型决定调用”当作审计证据。

MCP 规范可以帮助 Agent 发现和调用工具，但协议本身不替代业务系统的身份、授权和审批。接入 MCP Server 或其他外部连接器时，仍应按第三方服务审查：来源、版本、权限、数据流向、日志和撤销方式。

## 四、数据泄露：从输入、输出到日志一起管

数据安全评审可以沿着数据生命周期走一遍：

| 环节 | PM 要问的问题 | 产品控制 |
|------|--------------|----------|
| 收集 | 是否真的需要这项数据？用户是否知道用途？ | 最小化采集、分级授权、敏感字段脱敏 |
| 上下文 | 哪些数据会进入模型、检索、浏览器或第三方工具？ | 字段级过滤、租户隔离、目的限制 |
| 输出 | 模型是否可能复述或组合出敏感信息？ | 输出检测、权限过滤、敏感内容阻断或人工复核 |
| 外发 | 是否会发送到外部邮箱、SaaS、公开页面？ | 目标确认、域名/收件人限制、二次确认 |
| 存储 | 任务、记忆、评测集和日志保存多久？ | 保留周期、删除机制、访问分级 |
| 复盘 | Badcase 是否含真实个人信息或商业机密？ | 脱敏后入评测集，原始数据最小化留存 |

模型供应商关于数据是否用于训练、保留多久以及企业控制项的承诺会随产品、套餐和合同变化。**事实**应以当前供应商官方文档和合同为准，不能在 PRD 里凭经验写成“绝不会留存”；**建议**是把数据流向、处理目的和供应商条款作为上线闸门。

## 五、恶意网页与文件：浏览和阅读不是可信执行

网页、邮件、PDF、代码仓库和用户上传的文件，都可能包含诱导模型执行动作的内容。即使文件本身“看起来像资料”，其中的文字也不应自动获得系统权限。

建议把“读取内容”和“执行内容”彻底分开：

- 浏览器/文件工具默认以只读和隔离环境运行，不自动执行脚本、宏或下载的程序；
- 解析附件前做文件类型、大小、压缩层级和恶意内容检查；
- 把网页和文件中的指令作为待分析文本，禁止其覆盖系统策略或改变工具权限；
- 浏览外部网页时不要把高权限令牌、密钥和无关的内部资料放进同一上下文；
- 外部链接、收件人、上传目标和下载路径做 allowlist 或确认；
- 记录来源 URL/文件 ID、抓取时间、解析版本和后续工具动作，方便复盘。

> **推测**：如果一个公开 Demo 能根据网页内容自动发邮件或修改外部系统，仅凭演示结果无法判断它是否有沙箱、域名限制或人工确认。面试和案例分析时，应把这些问题列为“需要验证的安全假设”。

## 六、风险动作确认：把授权做成用户看得懂的交互

确认机制要解决的不是“用户点了一个按钮”，而是用户是否清楚地知道 Agent 将对谁、什么对象、以什么范围做什么动作。

| 动作 | 确认内容 | 额外要求 |
|------|----------|----------|
| 发消息/邮件 | 收件人、正文、附件、发送身份 | 允许编辑；敏感收件人或外部域名再次提示 |
| 删除/覆盖 | 对象、数量、是否可恢复 | 优先软删除或提供撤销；批量操作显示范围 |
| 付款/下单 | 金额、商品/收款方、账户、时间 | 强身份认证；不允许模型自行修改确认后的金额 |
| 权限变更 | 对象、角色、影响范围和有效期 | 管理员/人工审批；完整审计 |
| 公开发布 | 发布渠道、受众、内容和引用来源 | 内容复核、版权/隐私检查、可撤回 |

确认卡片应带有任务 ID、动作版本和过期时间。用户拒绝后，Agent 要进入明确的取消或改计划状态，不能换一个工具偷偷重复执行。

## 七、审计、告警与人工兜底

安全审计至少要能回答：谁在什么时候，以哪个 Agent/版本，基于哪些数据，提出了什么动作；系统为什么放行或拦截；谁确认了副作用；最终结果是什么。

建议记录：

- 用户、租户、Agent、模型、Prompt/Policy、工具和连接器版本；
- 读取的资源类型和来源、敏感字段处理结果；
- 工具参数摘要、权限判断、风险分级、确认记录和执行证据；
- Prompt Injection/越权/敏感信息告警、拦截动作和后续人工处理；
- 任务状态、重试、取消、回滚和最终用户通知。

告警不能只发给安全团队。产品、运营、安全、工程应预先约定事件等级、响应时限、关闭标准和评测集回流方式。出现无法判断的高风险状态时，宁可暂停并转人工，也不要让 Agent“再试一次”。

## 八、上线安全自查清单

- [ ] 已画出用户、模型、检索内容、网页/文件、工具和外部系统之间的信任边界。
- [ ] 外部内容默认视为不可信数据，不能覆盖系统策略或自动获得权限。
- [ ] 工具按只读、可逆写入、不可逆副作用和权限类动作分级。
- [ ] 服务端执行真实鉴权、租户隔离、参数校验、幂等和频率/范围限制。
- [ ] 高风险动作展示目标、范围、后果、数据和撤销方式，并要求当前用户确认。
- [ ] 敏感数据在采集、上下文、输出、外发、存储和日志环节都有控制。
- [ ] 浏览器和文件解析默认隔离，不自动执行脚本、宏或下载程序。
- [ ] 安全事件有审计日志、告警、人工接管、回滚和评测集回流路径。
